# LeadWidget — V1.0 Implementation Plan: Bulk Google Maps Capture

## 1. Immediate Implementation Target
The immediate implementation priority for LeadWidget is **V1.0 — Bulk Google Maps Capture**.

### 1.1 Strategic Rationale for Prioritizing V1.0
1. **Solves the Core High-Yield User Problem:** Google Maps accounts for the majority of local business discovery. Manually clicking 50 business panels to copy data is the primary point of friction for users. Bulk extraction directly solves this friction.
2. **Builds the Foundational In-Page Interaction Mechanics:** Injecting DOM selection affordances onto dynamic virtualized lists (`.hfpxzc` cards) establishes the interactive selection architecture needed by all future web sources.
3. **Validates Zero-Cost Batch Export First:** Before introducing complex asynchronous queues (V1.1), web crawling (V1.4), or AI LLM inference (V2.0), V1.0 proves out the core local-first storage and Google Sheets batch export pipeline in a controlled environment.

## 3. Explicit Version Scope Boundaries

### Included in V1.0
- Google Maps multi-card list extraction (`.hfpxzc`).
- Single-card selection checkboxes and "Select All Visible" mechanics.
- In-memory/storage synchronization across Maps scrolling.
- Real-time lead review queue in the extension popup.
- Google Sheets batch append via OAuth 2.0.
- Pre-export duplicate detection against existing sheet rows.
- Preservation of baseline single-business panel extraction.

### Excluded from V1.0 (Deferred to V1.1+)
- Multi-session persistent research queues (Deferred to V1.1).
- Unstructured editorial article and blog lead discovery (Deferred to V1.2).
- Automated Google Search enrichment lookups (Deferred to V1.3).
- Business website inspection and Contact/About scraping (Deferred to V1.4).
- Yelp and third-party business directory adapters (Deferred to V1.5).
- Groq AI RAG assistance and entity reconciliation (Deferred to V2.0).
- Team workspaces and commercial cloud backends (Deferred to V3.0).
